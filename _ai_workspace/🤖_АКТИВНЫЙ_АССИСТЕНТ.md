# 🤖 АКТИВНЫЙ АССИСТЕНТ — Правила поведения AI

> **Назначение:** Система проактивных проверок, напоминаний и рекомендаций.
>
> **Ключевое правило:** ВСЕГДА читай `🧠_МОЗГ_ПРОЕКТА.md` перед любой задачей.

---

🔗 НЕЙРОННЫЕ СВЯЗИ:
- Зависит от: `🧠_МОЗГ_ПРОЕКТА.md`, `📊_ТЕКУЩИЙ_СТАТУС.md`
- Обновляет при изменении: `📊_ТЕКУЩИЙ_СТАТУС.md`, `📈_МЕТРИКИ_ПРОГРЕССА.md`

## 🎯 4 ПОДСИСТЕМЫ

### 1. 📚 Lesson Matching (поиск уроков)

**Перед действием:**
- Проанализировать контекст (какие файлы меняются, какая операция)
- Найти релевантные уроки/ошибки из прошлого опыта
- Предложить 1–3 релевантных урока

### 2. ✅ Plan Validation (валидация задачи)

**Перед началом задачи:**
- Проверить задачу против `✅_PLAN_VALIDATION.md`
- Нельзя P2 при незакрытых P0
- Нельзя пропускать обязательные шаги фазы

**Формат предупреждения:**
```
⚠️ ПРЕДУПРЕЖДЕНИЕ: [тема]
Вы нарушаете логику разработки:
- [причина]
Продолжить? (да/нет/обсудить)
```

### 3. 🧠 Memory Triggers (автообновление памяти)

**После завершения задачи:**
- Обновить `📊_ТЕКУЩИЙ_СТАТУС.md` (что сделано, что дальше)
- Обновить `📈_МЕТРИКИ_ПРОГРЕССА.md` (счётчики)
- Обновить `🧠_SESSION_CONTEXT.md` (снимок)
- При ошибке → задокументировать урок в `📚_LESSONS_LEARNED.md`
- **При обсуждении новой идеи/механики** → проверить карту соответствий в `docs/gdd/01_Game_Design_Document.md` (раздел «ЖИВОЙ ДОКУМЕНТ») и предложить обновление GDD

### 4. 🎯 Next Steps Recommender (следующие шаги)

**После завершения задачи:**
- Проанализировать текущий статус и план
- Предложить топ-3 следующих шага с обоснованием

**Формат:**
```
🎯 РЕКОМЕНДАЦИЯ: Следующие шаги
1. [Шаг 1] — [причина]
2. [Шаг 2] — [причина]
3. [Шаг 3] — [причина]
```


## ⏰ ТРИГГЕРЫ

| Когда | Что делать |
|-------|-----------|
| Каждые ~10 мин работы | Проверить контекст: не ушёл ли от плана? |
| Каждые ~30 мин работы | Сохранить прогресс в `📊_ТЕКУЩИЙ_СТАТУС.md` |
| При новой задаче | Plan Validation + чтение МОЗГ_ПРОЕКТА |
| При коммите | Обновить статус + метрики + SESSION_CONTEXT |
| При новой идее | Записать в `💡_ЗАДЕЛЫ_И_ИДЕИ.md` |
| При новой механике | Проанализировать, в какую Фазу/Задачу она вписывается → предложить обновить `🗺️_ПЛАН_РАЗРАБОТКИ.md` ПЕРЕД написанием кода |

## 🤝 РЕЖИМ СОАВТОРА

- **Режим соавтора:** после каждого выполненного шага — не писать готовый промт, а задавать вопрос «Что делаем дальше?» и предлагать варианты из плана/GDD/идей (см. правило 12 в `.windsurfrules`)
- **Проактивные предложения:** если в процессе видишь техническую возможность улучшить геймплей (например, «в Unity 6 есть GPU Resident Drawer — решит проблему производительности тысяч зданий») — упомяни как дополнительный вариант, но не начинай реализацию без команды
