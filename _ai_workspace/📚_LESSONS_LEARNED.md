## 📖 ЖУРНАЛ УРОКОВ

### Сессия 2026-11-05 — Инициализация

#### Урок 1: Неполный перенос системы управления (процессный)
**Проблема:** При создании `_ai_workspace` по ТЗ были созданы 9 файлов, но `SESSION_CONTEXT` и `LESSONS_LEARNED` из эталона kinoplan не были предложены — пробел выявлен только при внешнем сравнении.
**Решение:** Добавлены оба файла (компактно: протокол + снимок в одном файле вместо 3 файлов kinoplan).
**Предотвращение:** При выполнении ТЗ сверять список с реальными возможностями эталона и предлагать недостающее — не ограничиваться буквой задания.

---

#### Урок 2: Шаблон URP = только новый Input System (технический, предотвращён)
**Проблема:** План атомарных шагов предполагал классический `Input.GetMouseButtonDown`, но Unity 6 URP-шаблон ставит `activeInputHandler: 1` — только новый Input System. Старый API выбрасывает `InvalidOperationException` в рантайме.
**Решение:** Проверили `ProjectSettings.asset` до написания кода, обновили план: `Mouse.current` / `Keyboard.current` из `UnityEngine.InputSystem`.
**Предотвращение:** Перед кодом, зависящим от настроек проекта (ввод, рендер, физика), проверять `ProjectSettings.asset` и `manifest.json`, а не предполагать дефолты.

---

#### Урок 3: Мгновенное применение ввода = дёрганая камера (технический)
**Проблема:** Вращение и зум применялись к transform сразу по сырой дельте мыши — камера дёргалась и «улетала», ощущение далёкое от CS2.
**Решение:** Разделить ввод и применение: ввод накапливается в целевые значения (targetYaw/targetPitch, pendingZoom), а камера догоняет их через экспоненциальное сглаживание `1 - exp(-k*dt)` — кадро-независимо и плавно.
**Предотвращение:** Любое управление камерой/движимым объектом — ввод в цели, применение через сглаживание (Lerp/Exp decay), не напрямую в transform.

---

#### Урок 4: Разворот массива вершин ломает индексы треугольников (технический)
**Проблема:** Для CW-полигонов делал `verts3d.Reverse()`, но индексы ear-clipping ссылались на старый порядок — меш скремблировался, заливка вылезала за границы. Плюс треугольники не учитывали Unity-конвенцию (передняя грань = обход по часовой сверху).
**Решение:** Вершины ВСЕГДА в исходном порядке; разворачивать только ПОРЯДОК ОБХОДА для ear-clipping; каждый треугольник переворачивать для нормали +Y.
**Предотвращение:** Триангуляция — менять только порядок обхода/индексы, никогда не переставлять сам массив вершин. Winding для Unity: сверху front face = CW.

---

#### Урок 5: Частичное обновление статуса = устаревший контент на GitHub (процессный)
**Проблема:** После задач обновлялись только журнал и фокус в 📊_ТЕКУЩИЙ_СТАТУС.md, но не чек-лист «ЧТО СДЕЛАНО» — он завис на дне 1. GitHub был синхронизирован, но показывал устаревший контент файла. Пользователь решил, что проект не пушится.
**Решение:** Обновлён чек-лист «ЧТО СДЕЛАНО» всеми достижениями (прототип 1.1–1.4, GDD 3.2.1/3.2.2, исследование, §7/8/10).
**Предотвращение:** Workflow after-task предписывает обновлять ВСЕ разделы статуса — чек-лист, а не только журнал/фокус. Проверять после каждого коммита: дата, чек-лист, журнал, фокус — все четыре актуальны.
